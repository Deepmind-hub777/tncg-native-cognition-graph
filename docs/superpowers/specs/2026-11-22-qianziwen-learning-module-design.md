# 千字文互动教学模块设计

## 意图

把用户提供的两份第一组 HTML 原型整合进本仓库，作为可继续扩展的《千字文》学习模块。先以“天地玄黃”完成可用的黄金样板，重点解决 Android Chrome 上无声与无法描红，再用同一数据结构和交互扩展全篇 250 组。学员页面不出现内部项目名称或缩写。

用户另提供四张《千字文》截图，仅作为视觉和布局参考，不作为文字、拼音、笔顺或音频来源。所有尚未由正式资料逐项核验的内容保持 `needs_review`，不可自动标为 `verified`。

## 目标

- 在现有仓库内提供移动端优先的静态教学模块，不另建独立仓库或引入未有必要的前端框架。
- 每组按统一顺序呈现：繁体四字原文 → 拼音 → 语音 → 简体中文解释 → 极简英语注解 → 意境插画/图像提示 → 标准笔顺描红 → 听音辨字。
- 建立恰好 250 组的结构化内容；每页四组，末页两组，共 63 页，并保留页码跳转、前后页与进度。先完成第一组全部验收，才推广其余 249 组。
- Android Chrome 上显示音频状态、错误与备用路径；页面不得自动播放。
- 修复书写画布叠层、Pointer Events、坐标/DPR、旋转适配、清除/撤销、范字显隐、独立书写和笔顺动画。
- 所有拼音、释义、英语、音频和笔顺资源具有可追踪的校订状态与来源。
- 测验每题四个不重复选项，答对 +10、答错 -2，提供反馈与重播。
- README 说明运行方式、资源格式、校订流程和 Android 真机验收步骤。

## 非目标

- 不在无法使用真实 Android Chrome 设备时声称真机验收通过。
- 不用系统字体轮廓或人工编造的字符笔画列表冒充标准笔顺。
- 不把截图当作正式文字、拼音、笔顺或音频来源，也不静默决定版本异文。
- 不在学员 UI 显示“TNCG”、QZW 等内部名称或项目缩写。
- 删除原“声调与跟读”四宫格。
- 不要求本阶段为 250 组全部生成独立插画；数据模型支持图像提示/资源及状态，样板可先呈现第一组图像提示或无字插画。

## 方案比较与选择

1. **直接修补一个 HTML 文件。** 起步最快、依赖少；但 250 组内容、分页、来源状态、音频与笔顺资源会继续挤在页面模板中，难以校订和复用。
2. **在现有仓库建立静态、数据驱动的教学模块，并以原型作样板。** 起步需拆分页面、样式、逻辑、数据与资源；可在不引入框架的前提下保留现有视觉与交互，支持校订和 250 组扩展。

采用方案 2（用户已确认）。模块放在 `09-learning-library/qianziwen/`，符合仓库学习资源归档结构。使用原生 HTML/CSS/JavaScript 与 JSON，直接静态托管；按职责拆分 UI、教学数据、音频和笔顺数据。除经许可核验的笔顺数据/必要运行时代码外，不增加运行时网络依赖。

## 关键设计

### 数据与校订

每组记录唯一序号与 ID、四字繁体原文、逐字拼音、简体释义、英语短注、图像提示/资源、整组音频/慢读/逐字音频引用、各类校订状态、来源说明及必要的异文备注。页面和测验由同一数据源渲染，不把内容硬编码到模板字符串。只有来源核对完成的字段可为 `verified`；其余显示清晰的“待校订”提示。截图只用于视觉/布局参考。拼音参照《新华字典》第13版逐字核验，句中多音字按语境选读音；正式文本以维基文库《千字文》繁體頁主文为初始转录底本并交叉核对，版本异文列入待审清单。

先实现 `天地玄黃` 样板。第一组通过完整验收、其音频样板经用户试听确认后，再推广其余 249 组。最终用结构校验约束 250 组数量、每组 4 个汉字、ID 唯一、63 页及选项唯一。正式文本来源另行选定并逐批核验；遇到简繁、注音、异文不一致时列入待审清单。

### 音频

提供资源清单与本地音频路径约定。第一组先制作整组正常语速、整组慢速及“天、地、玄、黃”四个独立汉字共六个 MP3，交用户试听确认；用户确认前不批量生成其余音频。点击触发播放；每个按钮呈现 idle/loading/playing/paused/ended/error 状态，支持暂停和重复播放。优先播放预生成的标准普通话 MP3，失败或缺失时尝试等待 `voiceschanged`、绑定 zh-CN voice 的浏览器 TTS；TTS 不支持或报错时显示明确原因和手动重试提示。检测 Android Chrome、应用内 WebView 和文件预览环境，避免静默失败。首屏不自动播放。

音频文件需具备明确的可再分发授权，README/资源清单记录声音来源、生成方法、格式、声线名称、生成时间与许可；不得把授权不明的系统语音导出为项目资产。第一组六个 MP3 尚未试听确认时不批量生成其余音频。

### 笔顺与书写

使用经许可核验、含逐笔 SVG path/中心线及笔画顺序的数据集；保留所需许可和来源说明。用 SVG 展示逐笔动画与范字，再在相同坐标视口上叠加透明书写层。不得从字形字体描边或从手工字符名称推导笔顺。每个字的数据有来源和 `strokeOrderStatus`。

书写层用 Pointer Events，捕获 pointer，设置 `touch-action: none`，根据元素矩形和 SVG/画布逻辑尺寸换算坐标；以 DPR 绘制并在 ResizeObserver/方向变化时重设尺寸，保留向量笔迹或提示用户清空。工具含清除、撤销、范字显隐、独立书写模式。第一组四字在动画与触控区域均通过数据来源核对后，才显示已校订。

### 页面、分页与测验

每页最多展示四组；通过函数计算末页并呈现两组。前后页、页码跳转和学习进度可键盘操作并有可访问名称。听音辨字题目范围为当前页或选定复习范围，四个选项从内容数据中抽取且不重复；正确 +10，错误 -2，显示反馈并支持重播。

意境图不生成文字；无现成图片时可显示一条简短图像提示与资源待补状态。学员 UI 不出现内部项目术语。

### 质量与验收

增加自动结构校验及音频/绘图/分页组件测试。使用可本地运行的轻量检查，不为原型引入大型应用框架。测试须覆盖 250 组/末页两组、重复 ID、非四字条目、重复测验选项、音频缺失/失败状态、Pointer 坐标、DPR resize/方向变化、撤销与清除。完成后重新读取内容文件并核验首尾组、计数和关键状态。

第一组完全验收顺序：先让用户试听六个 MP3 并确认声线；再在真实 Android Chrome 完成音频点击播放/暂停/重复播放、手指触控、多笔连续书写、清除/重写/隐藏范字及屏幕旋转检查；该真机验收通过后才扩展其余 249 组。用户的 OnePlus 12 已列在 O+ Connect；本执行环境尚未检测到 `adb`，测试前需通过现有投屏/控制连接实际观测设备。记录设备、Android/Chrome 版本、音频结果、书写结果、旋转结果和未通过项；桌面浏览器测试不得替代真机结果。没有真实设备记录则验收未通过。

## 约束与留给实现者的选择

- 保持静态托管、原生浏览器技术和本地资源优先；避免依赖远程 CDN 才能播放或书写。
- 笔顺数据集/运行时代码的具体版本须在实施时核对许可、数据格式和传统字覆盖；只打包所需内容，保留许可。
- 图像资产可先用提示与状态占位；页面必须清楚区分已有图像与待生成/待审核资源。
- 当前未建立 Android 浏览器真机观测会话，且本执行环境未检测到 `adb`；最终报告必须基于真实设备记录，不得用桌面测试替代。
- 用户截图只用于视觉/布局参考，不能作为正式文字、拼音、笔顺或音频来源。
- 第一组音频试听确认与真实 Android Chrome 验收都是推广其余 249 组的门槛。
