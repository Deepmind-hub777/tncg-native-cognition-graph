# Qianziwen Beta Release Implementation Plan

> **For agentic workers:** execute each checked item in order; retain the existing feature branch and the frozen v0.1-base release.

**Goal:** Publish an independently downloadable beta of the 250-group course with a responsive bilingual teaching-purpose page and the corrected group 46 pronunciation.

**Architecture:** Keep the course static and data-driven. Add one static page under `site/`, reuse the current rice-paper visual system, and add links from the learner home and listening page. Build a deterministic ZIP with a versioned manifest, then publish a new GitHub Release and verify its tag and asset URL.

**Tech Stack:** Static HTML/CSS, existing JSON lesson data, Python release packager, GitHub branch/release.

**Spec:** `docs/teaching-purpose.md`, `RELEASE.md`, `HANDOFF.md`.

## Global Constraints

- Preserve all unrevised lesson statuses as `needs_review`.
- Do not change or overwrite `qzw-v0.1-base`.
- The beta must be published to the existing feature branch and a new GitHub Release, with the ZIP attached.
- The new learner-facing page must not display internal project names or abbreviations.

## Review Focus

- Chinese and English sections preserve the existing teaching-purpose text.
- Page links work from both the main learner interface and the listening page.
- Mobile has no horizontal overflow; keyboard focus and contrast remain visible.
- Package name, manifest label, tag, and GitHub Release all use one beta version identifier.
- Release notes state that content and media remain under review and that beta is not a scholarly sign-off.
